# HH.ru → Битрикс24 коннектор

Сервис забирает новые отклики кандидатов с hh.ru и сразу создаёт карточки в отдельной воронке Битрикс24.
Один сервер обслуживает сколько угодно порталов клиентов. В каждом портале коннектор ставится как **локальное приложение**, маркетплейс не нужен.

## Что умеет

- **Отклик → карточка.** Создаёт сделку в выбранной воронке или элемент смарт-процесса (что именно, выбирается в настройках) и привязывает контакт кандидата с ФИО, телефоном и email.
- **Повторный отклик.** Если контакт уже есть в CRM (совпал телефон или email), новый контакт не создаётся. Используется существующий, а в названии новой карточки ставится префикс «Повторный отклик».
- **Комментарий и резюме.** В таймлайн карточки пишется комментарий: вакансия, город, зарплата, опыт, ссылка на резюме, сопроводительное письмо. PDF резюме прикрепляется туда же.
- **Ответственный.** Задаётся по каждой вакансии; для остальных действует ответственный по умолчанию.
- **Поля.** Данные из hh.ru можно разложить по пользовательским полям карточки: зарплата, город, возраст, ссылка на резюме и т. д.
- **Статусы в hh.ru.** При переводе карточки на стадию меняется статус отклика на hh.ru: отказ, приглашение, оффер и т. д. Можно добавить сообщение кандидату.
- **Несколько аккаунтов hh.ru.** К одному порталу подключается несколько менеджеров.
- **Отклики не теряются при сбоях.** Если hh.ru, Битрикс24 или сам сервер были недоступны, после восстановления коннектор сам проверяет весь пропущенный период и догружает отклики. Проверяются все стадии откликов в hh.ru (даже если рекрутер успел их разобрать) и вакансии, закрытые за это время. Загрузка в Битрикс24 повторяется без ограничения числа попыток. Раз в сутки идёт контрольная сверка за 3 дня, а на вкладке «Журнал» можно вручную догрузить отклики с любой даты (до 90 дней). Дубли исключены. Догруженные карточки помечаются в таймлайне.
- **Скорость.** Есть вебхуки hh.ru и дополнительный опрос каждые N минут. Всё видно в журнале.
- **Безопасность.** Токены в БД зашифрованы (AES-256-GCM), список порталов-клиентов ограничивается белым списком.

## Как это устроено

```
hh.ru ──(вебхук + опрос)──► коннектор (Node.js + PostgreSQL) ──REST──► Битрикс24
                                  ▲                                      │
                                  └──── событие «карточка изменена» ─────┘ → смена статуса на hh.ru
```

Стек: Node.js 22, TypeScript, Fastify, PostgreSQL 16, Docker Compose. Экран настроек сделан на чистом HTML/JS и открывается внутри Битрикс24.

## Шаг 0. Регистрация приложения на hh.ru (один раз на весь сервер)

1. Зайдите на https://dev.hh.ru → «Мои приложения» → «Создать приложение».
2. **Redirect URI** укажите `https://ВАШ_ДОМЕН` или `https://ВАШ_ДОМЕН/hh/callback` — приложение принимает оба. То же значение пропишите в `.env` в `HH_REDIRECT_URI`.
3. Дождитесь модерации (обычно несколько дней), затем скопируйте Client ID и Client Secret в `.env`.

> Без зарегистрированного приложения API работодателя (отклики, резюме, смена статусов) недоступен.
> Если у клиента есть своё приложение hh.ru, он может ввести его ключи в настройках, на вкладке «Подключение».

## Шаг 1. Установка на VPS

Нужен VPS на Ubuntu или Debian и домен, который указывает на этот сервер.

```bash
git clone https://github.com/ВАШ_АККАУНТ/newflat-hr-connector.git
cd newflat-hr-connector
bash scripts/check-server.sh      # покажет, что занимает 80/443, есть ли nginx и сертификаты
bash scripts/install.sh           # первый запуск создаст .env со случайными секретами
nano .env                         # заполните DOMAIN, PUBLIC_URL, ALLOWED_PORTALS, HH_CLIENT_ID/SECRET
bash scripts/install.sh           # второй запуск поднимет приложение
```

**HTTPS.** Битрикс24 и hh.ru работают только по HTTPS. Возможны два варианта:

- **На сервере нет своего nginx (порты 80/443 свободны).** `install.sh` сам включит встроенный Caddy, и он выпустит сертификат Let's Encrypt. Делать ничего не нужно.
- **На сервере уже есть nginx.** Скопируйте `deploy/nginx.conf.example` и подставьте свой домен (инструкция в начале файла). Приложение слушает `127.0.0.1:3000`.

Проверка: `https://ВАШ_ДОМЕН/health` должен вернуть `{"ok":true}`.

Обновление: `bash scripts/update.sh`. Резервная копия БД: `bash scripts/backup.sh`.

## Шаг 2. Подключение нового клиента (портала Битрикс24)

1. Добавьте домен портала в `ALLOWED_PORTALS` в `.env` и выполните `docker compose up -d`.
2. В портале клиента откройте **Разработчикам → Другое → Локальное приложение** и заполните:
   - Тип: **Серверное**.
   - «Использует только API»: **снять** галочку.
   - Путь вашего обработчика: `https://ВАШ_ДОМЕН/b24/app`.
   - Путь для первоначальной установки: `https://ВАШ_ДОМЕН/b24/install`.
   - Права: **CRM (crm)**, **Пользователи (user)**.
   - Сохранить.
3. Откройте приложение в меню портала:
   - **Подключение.** Вставьте client_id и client_secret из карточки локального приложения (они нужны для работы в фоне). Нажмите «Подключить аккаунт hh.ru» и войдите под менеджером компании.
   - **Воронка.** Выберите тип карточки, воронку, стадию и ответственного, затем включите интеграцию.
   - **Вакансии, Поля, Статусы в hh.ru.** Настройте по необходимости.
   - Нажмите «Сохранить настройки».

Рекомендуется заранее создать воронку «Подбор персонала» со стадиями (например, Новый отклик → Звонок → Собеседование → Оффер → Вышел / Отказ) и источник «hh.ru».

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DOMAIN`, `PUBLIC_URL` | Домен и внешний HTTPS-адрес |
| `SECRET_KEY` | Ключ шифрования токенов (не меняйте после запуска) |
| `POSTGRES_PASSWORD` | Пароль БД |
| `ALLOWED_PORTALS` | Белый список доменов порталов через запятую |
| `HH_CLIENT_ID`, `HH_CLIENT_SECRET` | Приложение с dev.hh.ru |
| `HH_REDIRECT_URI` | Redirect URI ровно как на dev.hh.ru (по умолчанию `PUBLIC_URL/hh/callback`) |
| `HH_USER_AGENT` | Обязательный для hh.ru заголовок: `Название/1.0 (email)` |
| `HH_WEBHOOK_EVENT` | Тип вебхука о новом отклике; пусто — только опрос |

## Разработка

```bash
npm install
npm test           # юнит-тесты
npm run typecheck
npm run dev        # нужен PostgreSQL и переменные из .env
```

Структура: `src/b24`: клиент REST Битрикс24; `src/hh`: клиент API hh.ru; `src/sync`: опрос, импорт, обратная синхронизация, планировщик; `src/routes`: HTTP; `views` и `public`: экран настроек.

## Ограничения и что проверить на живых данных

- Приложение рассчитано на **один запущенный экземпляр**: фоновые задачи не распределяются между копиями.
- Название события вебхука hh.ru (`HH_WEBHOOK_EVENT`) сверьте с актуальной документацией. Если подписка не удастся, это попадёт в журнал, а опрос продолжит работать.
- Набор действий над откликом (отказ, приглашение и т. д.) берётся из самого отклика на hh.ru. Если действие недоступно в текущем состоянии, в журнале будет ошибка со списком доступных.
